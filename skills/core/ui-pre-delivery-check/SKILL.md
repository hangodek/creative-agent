# UI Pre-Delivery Quality & Architecture Checklist

Before declaring any UI task, component, or view complete, you MUST verify your code against this 10-point quality and architecture gate. This prevents both subtle visual bugs and the most common architectural AI failure mode: **unsolicited feature bloat and duplicated constants**.

---

## The 10 Mandatory Pre-Delivery Checks

| # | Inspection Item | Verification Rule | Fix if Missing |
|---|-----------------|-------------------|----------------|
| 1 | **Strict Scope Restraint** | **Verify against the brief.** Build ONLY what the user asked for. If asked for a "todo list", DO NOT invent Profile pages, Cover pickers, or Kanban boards. One thousand no's for every yes. | Delete unsolicited pages, tabs, and bloated feature creep. Focus 100% on perfecting the core feature. |
| 2 | **Zero Duplicate Constants (DRY)** | Any styling dictionary (e.g. `CATEGORY_STYLES`, `STATUS_COLORS`), category array, or options list used in ≥2 files must live in a shared constants file. | Extract to `src/constants/theme.ts` or `src/types.ts`. Never copy-paste styling dictionaries across components. |
| 3 | **Component Line Budget (< 250 Lines)** | No component or root view should exceed 250 lines. Complex state logic (filtering, sorting, storage, theme) must not be stuffed into one monolithic file. | Extract state and handlers into clean Custom Hooks (`useTasks.ts`, `useTheme.ts`, `useFilters.ts`). |
| 4 | **No Emoji Icons** | All icons must use SVG primitives (Lucide / Heroicons / Phosphor). Never use Unicode emojis as UI control icons. | Replace `<span>🗑️</span>` with `<Trash2 className="w-4 h-4" />`. |
| 5 | **Clickable Cursor** | All interactive buttons, cards, tabs, and toggles must have `cursor-pointer`. | Add `cursor-pointer` to clickable button/div classes. |
| 6 | **WCAG AA Contrast** | Body text must achieve at least **4.5:1** contrast ratio against its direct background in both light and dark modes. | Darken muted text on light mode; brighten muted text on dark mode. |
| 7 | **Focus-Visible Rings** | Every button, link, and input must have an accessible focus indicator for keyboard users (`Tab` key navigation). | Add `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-offset-2`. |
| 8 | **Motion Accessibility** | Animations and spring transitions must respect `prefers-reduced-motion`. | Wrap transitions in `motion-reduce:transition-none` or `motion-safe:animate-...`. |
| 9 | **Responsive Fluidity** | UI must render without horizontal overflow, clipped badges, or awkward wrapping at **375px** (mobile), **768px** (tablet), and **1280px** (desktop). | Use `flex-wrap`, responsive grids (`grid-cols-1 sm:grid-cols-2 lg:grid-cols-4`), and `truncate`/min-width clamps. |
| 10 | **Tabular Numbers** | All columns containing numbers, prices, timestamps, or stats must use tabular figures to prevent horizontal jittering. | Add `tabular-nums` or `font-mono tabular-nums`. |

---

## Verification Protocol

Before declaring *"I have finished building the component"*:
1. Review your diff against all 10 checklist points above.
2. Confirm: **Did I keep the scope tight? Are all shared constants in one place? Is the code modular?**
3. If any check fails, refactor and fix it immediately before handing off to the user.
